## What is and is not demonstrated
The relation primitive itself is safe for these scalar fields; remove it as a standalone privacy blocker. The enclosing general update's compensation is a demonstrated scalar writer, not an imagined relation-column issue. It can execute after its scalar update and uses an earlier selected entity. Whether an adverse interleaving commits under a particular enclosing transaction/isolation is NOT proven and was NOT tested. Document Service has an existing transaction wrapper; query-builder honors its context. It would be false to claim a live exploit or universal loss of transaction protection. It would also be false to claim all authorized/direct Query Engine paths are protected by that wrapper or that presence of a transaction proves the required vendor-independent monotonicity.

UNCONTROLLABLE means no demonstrated project service/document/lifecycle interception of this internal compensation while keeping that general wrapper; it is not a theorem that Strapi can never be adapted. Replacing its persistence orchestration could remove the route, but a complete adapter preserving component/relation validation, rollback, return values and legitimate Admin saves has not been established. Simply invoking updateRelations outside its normal transaction/entry orchestration would silently change failure semantics. Patching node_modules, monkey-patching query execution, a distributed lock or assuming database isolation would not satisfy the closed design gate.

## Two-layer evaluation and CAS

Keep prior concrete scalar CAS candidate id+expected state+expected covered private scalars (explicit nulls); timestamp is not a proven unique version.
