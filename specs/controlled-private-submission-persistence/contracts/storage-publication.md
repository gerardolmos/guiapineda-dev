# Millorem storage + publication contract v1

## Evidence and supported boundary
Configured config/plugins.js is empty; installed Upload default local. Existing provider writes via fs.writeFile/createWriteStream to final hash.ext; high-level Upload generates random suffix and writes provider before Media add. Do not reuse high-level Upload for this adapter.
Node installed @types/node/fs.d.ts and fs/promises.d.ts map link to POSIX link(2). Local SDK man2/link.2 states atomic directory-entry creation, EEXIST without replacing destination, and same-filesystem requirement. That is the selected primitive, NOT overwrite-prone rename. SDK fsync.2 documents power-loss limits. No actual filesystem capability test/storage write performed in design. Future isolated QA and deployment qualification must verify link/sync support; unsupported FS/provider fails closed (EXDEV/ENOTSUP/EACCES), no copy/rename fallback.

## Identities / artifact
source_key = full trusted private documentId, immutable; command resolves source UID internally, not caller-selected target. O=versioned length-delimited UTF8 tuple [v1,source_key,main-image,quarantineID]. key=mp_ + SHA256(O) lowercase64hex + .webp. Canonical path under public/uploads/ with that filename. Hashing O is namespace derivation, SHA256(file bytes) is integrity, never cross-source dedupe. No raw source/title/path interpolation. Manifest stores O hash, Q, SHA256 normalized bytes, byte length,width,height,canonical key. Already-normalized WebP is copied byte-for-byte; no second random transformation. Media original URL is sufficient for existing MilloraCard.imatge.url; optional formats/previewUrl remain null, no new derivatives or generic upload changes.
Temp root: server-owned non-public sibling directory on SAME filesystem as uploads, mode0700; exclusive wx per-attempt filename in mp-v1 namespace. Canonical directory service-owned, no hostile symlinks/external writers; paths derived server-side, resolve root confinement and reject symlink/nonregular entries. No caller-controlled filesystem paths. No writes through temp inode after publication.

## Prepare and physical ensure
Approval transaction commits private state/revision AND source ledger with Q/approved source revision AND canonical draft target seeded once from validated public data. Same transaction ensures a failed approval leaves no target/operation. No filesystem effects before commit. Trusted source remains referenced in solicitud until at least complete canonical/Media/publication, and prerequisite does NOT delete it. If a later writer would alter captured Q during incomplete publication, conflict; no stale upload against changed source. Legacy intake checks below.
After commit read source using existing guarded quarantine reader, compute normalized byte hash/length/dimensions without modifying source. Persist complete immutable manifest with ledger CAS before any physical write. Concurrent preparation loser reloads manifest; differing content/Q conflicts. No-image operation has manifest=null and follows no-file branch.
1 If canonical exists, open read-only/no-follow as supported, verify regular file, full SHA256 and length against manifest; match→reuse; mismatch→integrity conflict, never overwrite/delete.
2 Otherwise create own private temp wx, copy source while hashing, verify expected bytes, FileHandle.sync, close all writable descriptors. No direct exclusive write to canonical: crash would expose truncated canonical. No rename over existing file.
3 fs.promises.link(temp,canonical). Success creates one canonical directory entry pointing to complete closed inode. EEXIST means another attempt won: verify winner bytes; never rewrite it. Other errors fail closed. Sync canonical parent directory where supported; sync failure reported, not success. Temp must be same filesystem; no network FS semantics assumed.
4 Unlink ONLY own temp after winner verification; hardlink removal cannot remove canonical. A crash may leave temp names, not additional canonical/public assets. Never mutate temp bytes after link. Record STORAGE_READY only after verification; manifest can lag file and recovery repeats step1.

## Temporary cleanup and cleaner
Own-attempt normal cleanup may remove only its owned temp. Crash leftovers: explicit cleanup with24h grace AND all adapter workers/attempts paused/drained; mtime alone never proves abandoned. Exact namespace/regular-file/root checks; no traversal, symlink following or canonical removal. No background cleaner added.
Existing private-submission-image-cleanup lists only quarantine root and recognized32-character private image filenames; canonical mp_64hex.webp is in uploads and temps outside quarantine. It cannot delete these. Keep private Q referenced while recovery may need it; after publication retention remains unchanged for later scoped policy, no blob deletion in this prerequisite. Source missing before canonical exists→safe failure requiring human, never invent bytes. Missing/corrupt canonical after publication detected on ensure; recover only from retained matching source with explicit error handling, never overwrite a mismatch.

## Ledger schema / states
Internal non-draft/nonlocalized collection; no public CRUD routes or general Admin editing. source_key:string required immutable + REAL database unique constraint through supported column.unique/model index; no reliance solely on schema validation. revision:integer1..2147483647 default1 server-only. state:enum PREPARED,STORAGE_READY,MEDIA_READY,LINKED,PUBLISHED defaultPREPARED. target_document_id:string required after creation transaction. image_manifest:private JSON nullable for no image; contains immutableQ/opkey/hash/size/dimensions/key after preparation. media_id:integer nullable. last_error_class:string nullable fixed allowlist. Standard timestamps. No redundant source_document_id or media_document_id: source_key is X; upload Media's numeric id is canonical plugin identity. No added public Millora or Media schema. These7 custom fields plus automatic metadata are sufficient.
PREPARED guarantees target draft, sourceQ recorded (image manifest may contain Q with remaining fields pending; explicit prepared=false until full hash persisted). STORAGE_READY guarantees complete immutable manifest and verified canonical, or no-image branch. MEDIA_READY guarantees media_id references canonical Media or no-image branch. LINKED guarantees draft relation/content ready. PUBLISHED guarantees target document published and canonical identity retained. Error code orthogonal, state never regresses on retry. Manifest shape has preparation flag; state progress claims only durable facts. No publication-stage status merely from memory.
State/receipt changes use transaction CAS revisionN→N+1 on unique ledger ID. Retry after CAS conflict reloads stage explicitly; no blind side-effect replay. Physical ensure is safely concurrent independent of DB lock because same complete bytes/key/link. DB transaction not held across physical write.

## Media and target atomicity
After canonical verification: BEGIN ledger CAS; if media_id present, fetch and validate metadata key/url/provider/hash. Else create plugin::upload.file using supported db.query.create (no upload), required metadata validated: name mp_<key>.webp,hash mp_<key>,ext.webp,mime image/webp,size bytes/1000,width,height,url /uploads/mp_<key>.webp,provider local,folderPath '/',formats null. Set media_id and MEDIA_READY in SAME transaction. Events/metrics only aftercommit, no manual storage rollback. Any component/Media hook throwing rolls back both row and ledger pointer. No new Media unique field required: one unique-source ledger and actual CAS serialize registration. Duplicate source insert loser exits failed transaction, opens new lookup of winner.
'Crash after Media create before receipt' cannot commit only Media: same DB transaction rolls back on connection/process failure. Lost response after commit persists BOTH, retry reads media_id. Unexpected persisted Media with absent receipt is inconsistent legacy/out-of-band state: safe conflict, do not create a second Media by heuristic filename search. No promise to repair arbitrary DB tampering.
Target draft creation occurs atomically with first ledger assignment. All future calls use target_document_id, not slug. Draft/published rows may share documentId under D&P; canonical DOCUMENT identity is one. No unique public source field that would conflict with D&P variants. Final transactions ledger CAS→validate/attach Media→LINKED then publish via documents(PUBLIC_UID).publish→PUBLISHED, with publish and ledger completion in one transaction. Re-read return target; response loss reloads PUBLISHED. Publishing parent private source does not use unsafe parent update. Public D&P internal updates are outside the six scoped private PII types; transactionally preserve canonical target identity.

## Visibility / editorial protections
Generated draft cannot publish before MEDIA_READY and completeness; narrow project document middleware blocks manual publish/clone/delete of linked generated target that violates ledger. In every state before PUBLISHED the image slot is system-owned and changes conflict; scalar public editorial edits allowed and never overwritten by retry. First create seeds public data once. After PUBLISHED all ordinary public editorial fields/images may be edited independently; ensure returns same P and never reapplies source payload or silently republishes editorially unpublished target. If target deliberately unpublished/deleted, return editorial conflict; no recreate/republish. Ledger remains durable identity.
Adapter-owned Media file replacement/deletion through Upload routes is blocked by narrow project middleware before provider mutation while any ledger references it; metadata-only edits allowed if they do not change storage identity. No global upload service patch; trusted unrelated services must not manipulate this namespace. Whole local upload service remains unchanged for all other assets.
Reopen/reapprove same X returns same P, preserves public edits. Same Q is idempotent. Changed Q before first publish conflicts until explicit cancellation/reconciliation; no silent switch of an in-flight manifest. Changed Q after publish/reapprove returns existing P plus source-image-changed requiring explicit public editorial update; no auto overwrite or second target. Thus identity safe, not a source-sync feature. Each image O is immutable; no generation cleanup added.

## Failure windows A–J
A before temp: retry from manifest/source. B during temp: canonical absent, own leftovers ignored until quiesced cleanup. C completed temp before link: retry can start another temp, canonical still unique. D after link: verify canonical. E before manifest state advancement: PREPARED+file reconciles verification→STORAGE_READY. F after advancement: reverify, reuse. G before Media: register. H after Media insert before ledger receipt: transaction rollback; after commit both receipt+row visible. I after relation: relation/state transaction rollback or both committed, retry from ledger. J after publish: publish/state transaction both committed or neither; retry returns same target. No cross-resource atomicity claim. No filesystem rollback after DB failure; deterministic verified artifact is reusable durable progress.
Transient file/DB failure: retryable fixed code, no automatic infinite loop. State/source/CAS/integrity mismatch:409 conflict or integrity failure requiring review. Missing committed target/Media or corrupt canonical: human investigation, never destructive repair. Disk/power loss outside OS durability not claimed solved; detect and safely recover only when original manifest-matching source exists. No distributed exactly-once claim; one canonical artifact/Media/document per source operation under controlled writers.

## Logs
Only source/operation/key hash,target/Media IDs,stage,outcome,fixed error class. No contact data,source free text/raw exceptions. Hashes computed only in future authorized adapter, never real data during SDD.

## Prospective eligibility / deployment contract
config/millorem-publication.js defines immutable operational cutover UTC supplied at separately authorized deployment; missing/invalid cutoff disables new source publication. Source createdAt is server-managed and must be strictly after cutoff for automatic new-ledger creation. All pre-cutoff/equal/unknown dates require verified manual source→target mapping and never auto-create. No client timestamp override. Source writes are frozen while cutoff/schema/backfill/release activate, so no mixed writer can enter this interval. Cutoff never advances on restart; changing it is a human operation with review. Local tests inject cutoff without .env edits.
