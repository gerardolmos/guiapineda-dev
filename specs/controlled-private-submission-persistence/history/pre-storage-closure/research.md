# Local installed API findings

Strapi @strapi/core5.41.1 (package.json). No web lookup, database calls, imports/bootstrap or transaction execution.

SUPPORTED: database/dist/index.d.ts declares transaction(callback) and transaction(); index.js:56-96 implements framework transaction using connection.transaction and AsyncLocalStorage context. Callback resolves→commit, throws→rollback/rethrow. query/query-builder.js:464+ applies ambient transaction. No vendor SQL needed. Transactions already wrap Document Service repository actions.

IMPORTANT CORRECTION: nested transaction shares ambient trx; nested commit/rollback helpers are no-ops when notNestedTransaction is false. Thus entity-manager.update relation catch inside an outer transaction does NOT itself end that outer transaction. Its full-row compensation remains inside it, then throws; uncaught error reaches outer rollback. Earlier reports correctly identified the scalar write but did not establish this nesting fact. Do not present a committed rollback resurrection as observed or inevitable. Exception swallowing or direct paths outside a mandatory outer transaction remain relevant to coverage.

SUPPORTED: strapi.documents.use middleware, source document-service/index.js and middlewares/middleware-manager.js. Runs around repository methods; context uid/action/params and next() permit six-type scoped routing. Content Manager document-manager.update calls documents.update, so server Admin update officially interceptable. No custom public controller required. Middleware must preserve existing Commerce guard/order/permissions. Async request capability may reject direct Query Engine callers; never serializable bypass flags.

COMPONENT API: documents component-extension.d.ts declares updateComponents and omitComponentData; index.js explicitly excludes these helpers from middleware wrapping. Their presence is stronger evidence than assuming all component internals inaccessible. However invoking helper alone neither reproduces full entry validation/transform nor supplies a complete replacement parent relation persistence/response/event contract. Full existing documents.update preserves these but still executes internal compensation on failure.

LIFECYCLES: timestamps subscriber beforeUpdate overrides updatedAt with new Date; beforeUpdateMany only assigns timestamps to array data, so scalar object needs explicit timestamp design. Hooks run from entity-manager, not raw query builder. Existing project register installs Commerce document guard; no extra private-type custom lifecycles found. Delegation via next preserves regular validation/hooks; splitting into updateMany changes lifecycle names and component orchestration.

CAS: expected status alone misses same-state edits. updatedAt/status has no installed uniqueness guarantee; two updates in the same timestamp resolution can share it. No logical version field found. Forcing strictly monotonic updatedAt using a scoped lifecycle is a candidate but must prove round-trip precision and preserve framework timestamp/consumer behavior. Not yet validated vendor-independently. General Admin transformDocument removes non-schema metadata (EditView/utils/data.mjs removeFieldsThatDontExistOnSchema), so do not assume the original timestamp reaches server update automatically. Server-reading updatedAt at save time is not an editor baseline. Need a supported UI baseline transport/response contract; middleware interceptability alone does not solve it. PII CAS from017 checks privacy fields but cannot detect all component/editorial stale changes and is not accepted as complete FR07.

Transactions can group scalar/component/relation writes: YES via existing documented-in-types callback and ambient queries; this does not prove a replacement with zero internal snapshot calls. Candidate wrapper CAS→next→verify inside outer transaction may CONTAIN unsafe effects if every writer participates and exceptions propagate; it does not ELIMINATE the framework snapshot rewrite. Distinguish transaction containment from user's stronger no-snapshot-compensation pipeline before approval.
